# Anime2.5DRig

デモ: https://852wa.github.io/Anime2.5DRig/

パーツ分けPSDをブラウザにドロップするだけで、自動リギングされて動き出す 2.5D アバターツールです。
従来は手作業だったセットアップ（メッシュ分割・変形・物理設定）を自動化します。インストール不要・全処理クライアントサイド。

## デモ / 使い方

1. このリポジトリを GitHub Pages で公開（Settings → Pages → Branch: main / root）するか、ローカルで:
   ```
   python -m http.server 8000
   # → http://localhost:8000
   ```
2. ページを開き、パーツ分けPSDをドロップ、または「サンプルAを読み込む」「サンプルBを読み込む」を選択。Aは `sample2.psd`、Bは `sample.psd` です。左上の「サンプルA」「サンプルB」から、読み込み後もいつでも切り替えられます。
3. 自動リグが走り、その場でアイドルモーション・まばたき・口パク・髪物理付きで動きます。

## 編集と保存

- 上部の「PSDを開く」からいつでもモデルを変更できます。読み込み中は進捗が表示され、「読み込みを中止」で取り消せます。新しいPSDが読み込めなかった場合も、編集中のモデルは残ります。
- 「設定を検索」で目・髪・口などのセクションを絞り込みます。セクション見出しはクリック、Enter、Spaceで開閉できます。
- スライダー右の数値は直接入力できます。スライダーをダブルクリックすると、その項目だけ初期値に戻ります。
- 「レイヤー」で表示／非表示、濃さ（不透明度）、奥行き、描画順を調整できます。上が奥・下が手前です。奥行きは首振り時の移動量に影響し、描画順とは別の設定です。
- 「調整を保存」で、パラメーター・自動動作・背景・レイヤー設定をブラウザ内にモデル別で保存します。同じ内容のPSDを読み込むと復元されます。「保存状態に戻す」で直前の保存状態に戻せます。
- 別のブラウザ／PCに移すときは「設定JSONを書き出す」を使用します。同じPSDを開いて「設定JSONを読み込む」で適用できます。PSDの画像そのものや、カメラ・マイクのON状態は設定JSONに含まれません。PSDを編集し直した場合は別のモデルとして扱います。
- 「一時停止」（入力欄の外ではSpaceも使用可）で動きを止め、数値を調整できます。「PNG保存」は現在のポーズを元のPSDサイズの透過PNGで書き出します。背景や操作画面は含みません。
- 「軽量PSDを保存」はノイズ除去・トリミングを行ったPSDを保存します。動き・描画順・奥行きなどの調整は設定JSONに保存してください。
- 表情プリセット中は自動まばたき・ランダム口パクによる上書きを抑えます。カメラ入力を使用するときも、自動まばたき・ランダム口パクより追跡値を優先します。

変更内容と今後の提案は [IMPROVEMENTS.md](IMPROVEMENTS.md) にまとめています。

## OBS 透過出力

1. `start_obs.bat` をダブルクリックし、開いた通常ブラウザでカメラを許可します。このブラウザが顔追跡を担当するため、配信中は閉じないでください。
2. OBSで「ブラウザ」ソースを追加し、URLを `http://127.0.0.1:8000/?obs=1&cam=1`、幅・高さをモデルに合わせて設定します。
3. OBS専用表示は背景が完全透過になり、操作パネルやパラメーター、FPS表示は映りません。`sample.psd` は自動で読み込まれます。

Python 3が必要です。自動検出できない場合は環境変数 `ANIME25D_PYTHON` に `python.exe` のパスを設定できます。ポート8000を別のアプリが使用している場合は `python obs_server.py --port 8001 --open-browser --camera` で起動し、OBSのURLも同じポートに変更してください。

`cam=1` は起動時にカメラ追従へ自動で切り替える設定です。通常ブラウザで計算した追跡値をOBSブラウザソースへ直接転送するため、OBS自身にカメラ許可は不要です。カメラ追従を使わない場合はURLから `&cam=1` を削除してください。

追跡が約1.2秒届かない場合は通常の動作に戻ります。カメラ／マイクをOFFにするとデバイスと処理を解放します。OBS中継は `obs_server.py` を起動したローカル環境で有効になり、同じオリジンからの検証済み数値だけを受け付けます。映像・音声そのものは中継しません。

閉じ目レイヤーに `eyeclose2`（または `eye_close2`）を追加すると、通常の `eyeclose` / `eye_close` と 4:1 の確率で切り替わります。`eyeclose2` の閉じ時間は通常瞬きの10倍です。

> カメラ追従（MediaPipe FaceMesh）とマイク口パクは https または localhost でのみ動作します（ブラウザの権限仕様）。file:// 直開きでもドロップ再生は可能です。

## 自動で行われること

- [see-through](https://github.com/shitagaki-lab/see-through) の出力PSDをそのまま受け入れ（`mouth`→`mouth_open` 自動リネーム）
- **閉じ目・閉じ口差分が無い場合、汎用差分を自動生成**（アンカーに合わせてスケール・配置し、まつ毛/口の色に自動調整。専用バーで位置・角度を微調整可能）
  - 差分の元絵はリポジトリ直下の `eye_close.psd`（左右両目を1枚・間を空けて）/ `mouth_close.psd` を優先使用。無ければ内蔵データを使用
- 低アルファノイズ除去（連結成分フィルタ）
- フォルダ内を含む可視画像レイヤーの再帰読み込み
- 目・眉・まつ毛・閉じ目の**左右自動分離**（連結成分の重心で判定）
- まぶた位置・虹彩中心・口・首ピボットなど**アンカーの自動検出**
- 髪の**房（ストランド）自動検出**（毛先輪郭のピーク検出、1レイヤーにつき最大6房）
- レイヤーごとの深度割当てによる**擬似3D首振り**（パララックス+シアー）
- 房ごとの2重バネ物理（**根元は固く・毛先はふわふわ**）、胸の揺れ、呼吸
- 閉じ目/閉じ口差分の**クロスフェード**、瞳のステンシルクリップ（白目内に制限）

## レイヤー命名規約

レイヤー名（日本語の「のコピー」や全角文字は自動正規化されます）:

| レイヤー名 | 内容 | 必須 | 備考 |
|---|---|---|---|
| `face` | 顔ベース | ◎ | アンカーの基準。これだけは必ず |
| `eyewhite` | 白目（左右両方） | ○ | 左右は自動分離 |
| `irides` | 虹彩（左右両方） | ○ | 視線移動・瞳スケール対象 |
| `eyelash` | まつ毛（開き目） | ○ | |
| `eye_close` | 閉じ目 | ○ | まばたきでクロスフェード |
| `eye_close2` / `eyeclose2` | 長い閉じ目 | | 20%の確率で使用、閉じ時間10倍 |
| `eyebrow` | 眉（左右両方） | ○ | 角度・上下操作対象 |
| `mouth_open` | 開き口 | ○ | 開度で顎が下がる |
| `mouth_close` | 閉じ口 | ○ | |
| `nose` | 鼻 | | |
| `ears` | 耳 | | |
| `earwear` | 耳飾り | | |
| `neck` | 首 | | 上端は頭に追従 |
| `topwear` | 上半身の服 | | 呼吸・胸の揺れ対象 |
| `bottomwear` | 下半身の服 | | |
| `handwear` | 腕・手 | | 腕の高さ操作対象 |
| `headwear` | 帽子・カチューシャ等 | | |
| `front hair` | 前髪 | | 房物理+3ブロック操作 |
| `back hair` | 後髪 | | 房物理 |

- **髪を複数レイヤーに分ける場合**: `front hair_1`, `front hair_2`, `back hair_1` … のように `_連番` を付けると、各レイヤーが独立した房グループとして物理演算されます（房数はレイヤー幅から自動決定）。
- 規約にない名前のレイヤーも読み込まれます（位置から頭部/胴体を推定して追従のみ）。
- レイヤーグループ（フォルダ）内の画像レイヤーにも対応します。非表示のフォルダ・レイヤーは読み込みません。
- **首（neck）と胴体（topwear）について**: see-through の出力をそのまま使うと首と胴体の前後関係の解決が難しく、動かした際に境目が破綻することがあります。うまくいかない場合は、首を胴体レイヤーに統合した**一体型**（neckレイヤーなし、topwearに首まで含める）にした方が成功しやすいです。
- キャンバスは正方形推奨（768×768〜2048×2048で動作確認）。

## 機能

表情プリセット（笑顔/驚き/ジト目/ウインク左右）、左右独立の目の開き、眉角度（左右独立+対称）、視線、瞳スケール、目/口の「閉じやすさ」しきい値、前髪3ブロック操作と**前髪専用の揺れ・柔らかさ**、腕の高さ/位置、胸の揺れ（強さ・位置調整可）、体の傾き、アイドル/ランダムモーション、ランダム口パク、マイク口パク、マウス追従、**ウェブカメラ追従**（頭XYZ・まばたき左右・口・視線）、背景切替（透過/グリーンバック）。

## 構成

```
index.html      画面構成
lib/app.css     スタイル・レスポンシブレイアウト
lib/app.js      編集UI・WebGL描画・デバイス入力
lib/runtime.js  入力／設定検証・メッシュ上限・バネ計算
lib/psd-worker.js  PSDの解析と自動リグ（バックグラウンド処理）
lib/rigger.js   自動リグ生成（純TypedArray実装、Node でもテスト可能）
lib/ag-psd.min.js  PSDパーサ（ag-psd, MIT）
lib/genericparts.js  汎用閉じ目・閉じ口差分（内蔵フォールバック）
eye_close.psd    閉じ目差分の元絵（任意・差し替え可）
mouth_close.psd  閉じ口差分の元絵（任意・差し替え可）
sample2.psd     サンプルA
sample.psd      サンプルB（OBS専用表示の初期モデル）
obs_server.py   ローカル配信・OBSへの追跡値中継
tests/          Node・Python・ブラウザの回帰テスト
```

ランタイムは WebGL1（メッシュワープ+ステンシル）。PSDはブラウザ内で処理し、サーバーへアップロードしません。カメラ追従を有効化した時は MediaPipe のコードとモデルをCDNから取得します。OBSの追跡値は同じオリジンのタブ間、またはローカル中継サーバー経由で送ります。

## 開発時の検証

追加パッケージは不要です。Node.js 18以降とPython 3を使用します。

```sh
node tests/rigger.test.js
node tests/runtime.test.js
node tests/psd.test.js
python -m unittest discover -s tests -p "test_*.py"
```

ローカルサーバーを起動して `http://localhost:8000/tests/browser.html` を開くと、ブラウザの回帰テストも実行できます。合成したテストPSDと仮想入力を使い、実際のカメラ・マイクにはアクセスしません。設定保存、PNGの透過画素、瞳クリップ、入力の取消、描画復旧、狭い画面を検証します。

## 既知の制限

- 一枚絵の分解はアプリ内では行いません。[see-through公式デモ（HuggingFace Space）](https://huggingface.co/spaces/24yearsold/see-through-demo)等で分割したPSDをドロップしてください（後処理は全自動）
- 口の開きは差分切替+変形の簡易表現（中間差分が増えると滑らかになります）
- 初期深度は名前ベースですが、読み込み後にレイヤーごとに調整できます。
- PSDはRGB・8bit/チャンネル、128MB以下、2400万画素以下、一辺16384px以下に対応します。さらに、レイヤー合計画素数・解析メモリ・端末のGPU上限によって読み込めるサイズが制限されます。
- フォルダの可視性は反映します。グループ合成、不透明度のグループ継承、特殊な描画モード、調整レイヤー、マスク効果の完全な再現は対象外です。必要な効果は画像パーツへ統合してください。
- `file://` 直開きでは解析がメインスレッドになり、解析中に中断できない場合があります。進捗・中断を使う場合はlocalhostまたはHTTPSで開いてください。
- 設定保存にはブラウザのローカルストレージを使用します。プライベートモード・容量制限等で保存できない場合はJSONを書き出してください。
